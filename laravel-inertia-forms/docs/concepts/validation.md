# Validation

Each field builds its own Laravel validation rules from its configuration. You add extra rules when you need them, and validate the request with one call.

```php
TextInput::make('email')->email()->required()->rule('unique:users,email');
// Rules: ['required', 'string', 'email', 'unique:users,email']
```

## How rules are built

For every field, the rule list is built in this order:

1. **Presence**: `required` if you called `->required()`, otherwise `nullable`.
2. **Type rules** generated by the field (see the table below).
3. **Your rules** from `->rules()` and `->rule()`, in the order you added them.

### Generated rules per field

| Field | Generated rules |
| ----- | --------------- |
| [TextInput](/fields/text-input) | `string`, plus `email` or `url` for those types, `min:`/`max:` from `minLength()`/`maxLength()` |
| [TextInput](/fields/text-input) with `number()` | `numeric`, `min:`/`max:` from `min()`/`max()` |
| [Textarea](/fields/textarea) | `string`, `min:`/`max:` from `minLength()`/`maxLength()` |
| [Hidden](/fields/hidden) | none |
| [Combobox](/fields/combobox) | `in:` the option values |
| [Combobox](/fields/combobox) with `multiple()` | `array` on the field, `in:` option values on `field.*` |
| [Radio](/fields/radio) | `in:` the option values |
| [Checkbox](/fields/checkbox) / [Toggle](/fields/toggle) | `boolean`, or `in:` the custom true/false values |
| [CheckboxGroup](/fields/checkbox-group) | `array` on the field, `in:` option values on `field.*` |
| [DatePicker](/fields/date-picker) | `date`, `after_or_equal:`/`before_or_equal:` from `minDate()`/`maxDate()` |
| [TimePicker](/fields/time-picker) | `date_format:H:i` (or `H:i:s`), `after_or_equal:`/`before_or_equal:` from `minTime()`/`maxTime()` |
| [ColorPicker](/fields/color-picker) | `regex:/^#[0-9a-fA-F]{6}$/` |
| [Slider](/fields/slider) | `numeric`, `min:`, `max:` |
| [FileUpload](/fields/file-upload) | `file` or `image`, `extensions:`, `max:` (per file); `array` and `max:` count when `multiple()` |
| [Submit](/fields/submit) | no rules, no value |

You can inspect the result at any time:

```php
ContactForm::make()->rules();
// [
//     'name'  => ['required', 'string', 'max:50'],
//     'email' => ['required', 'string', 'email'],
//     'plan'  => ['nullable', Illuminate\Validation\Rules\In { ... }],
//     ...
// ]
```

## Adding rules

`rules()` accepts a pipe-separated string or an array. `rule()` adds one rule, which can be a string, a rule object, or a closure.

```php
use Illuminate\Validation\Rule;

TextInput::make('username')
    ->required()
    ->rules('alpha_dash|min:3')
    ->rule(Rule::unique('users', 'username'));

TextInput::make('coupon')->rule(function (string $attribute, mixed $value, \Closure $fail) {
    if ($value !== null && ! Coupon::valid($value)) {
        $fail('This coupon has expired.');
    }
});
```

::: tip Pipes inside a rule
A string passed to `rules()` is split on `|`. For a regex that contains a pipe, use `rule()` or pass an array.
:::

## Required and nullable

- `->required()` adds `required` and shows a `*` next to the label.
- Without it, the field gets `nullable`, so an empty value passes and other rules are skipped for it.

::: tip Checkboxes and toggles
On a [Checkbox](/fields/checkbox) or [Toggle](/fields/toggle), `required()` means "must be switched on". It generates `accepted` (or `in:<trueValue>` for custom values), which is what you want for "I agree to the terms":

```php
Checkbox::make('terms')->label('I agree to the terms')->required();
```
:::

## Hidden fields are skipped

Only fields that are **visible** for the submitted data get rules. When a [visibility condition](/concepts/visibility) hides a field (or its fieldset), that field is not validated and is not included in the validated data.

To decide what is visible, the form merges the request input over its initial values from `data()`. Fields that were not submitted fall back to their initial (or bound) value.

[Unauthorized](/concepts/authorization) fields are removed completely, so they are never validated either.

## Validating a request

### `$form->validate()`

Call `validate()` with a request (or no argument to use the current request). It returns the validated data.

```php
public function store(Request $request)
{
    $data = ContactForm::make()->validate($request);

    Message::create($data);

    return back();
}
```

On failure it throws a `ValidationException`. Laravel redirects back and Inertia passes the errors to `<Form>`, which shows each message under its field.

If the form itself is not authorized, `validate()` throws an `AuthorizationException` (HTTP 403).

### The `#[Validate]` attribute

Put `#[Validate]` on a controller parameter typed as your form class. Laravel resolves the form from the container and validates the current request before your method runs.

```php
use Erag\InertiaForms\Attributes\Validate;

public function store(#[Validate] ContactForm $form)
{
    Message::create($form->validated());

    return back();
}
```

Using the attribute on a parameter that is not a `Form` subclass throws an `InvalidArgumentException`.

::: tip Update forms
The attribute creates a fresh form with no bound model and no route. When visibility or rules depend on the model being edited, validate manually instead:

```php
public function update(Request $request, Post $post)
{
    $post->update(EditPostForm::make()->bind($post)->validate($request));

    return back();
}
```
:::

### `validated()`

After a successful `validate()`, read the data again with `validated()`. Pass a key (dot notation works) to read one value, with an optional default.

```php
$form->validated();                        // all validated data
$form->validated('email');                 // one value
$form->validated('address.city', 'N/A');   // nested value with a default
```

Only fields that had rules are included. Extra input that the form doesn't know about is dropped.

## Error messages and attribute names

Field labels are used as attribute names in error messages. A field labelled "Work email" produces "The Work email field is required."

Override messages and attribute names by adding `messages()` and `attributes()` to your form:

```php
class ContactForm extends Form
{
    public function messages(): array
    {
        return [
            'email.required' => 'We need your email to reply.',
            'terms.accepted' => 'Please accept the terms to continue.',
        ];
    }

    public function attributes(): array
    {
        return [
            'email' => 'email address',
        ];
    }
}
```

Entries in `attributes()` take priority over labels.

## Showing errors

`<Form>` reads Inertia's error bag and shows the first error under each field. Errors for array items (like `tags.0`) are shown under the parent field (`tags`). When the user changes a field, its errors (including item errors) are cleared.
